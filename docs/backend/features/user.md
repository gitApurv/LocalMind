# User (`com.localmind.user`)

Owns the `users` table: the account record (email, BCrypt password hash, display name, custom instructions) that every
other feature references by `user_id`. It is a persistence-only feature with no service or controller; account
workflows (register, login, profile) live in the [auth feature](auth.md).

## Responsibilities

- Map the `users` table (`User` entity) and generate the user id and `created_at`.
- Provide lookups by id and by email, and an existence check by email (`UserRepository`).

## Package layout

| Class | Layer | Role |
| --- | --- | --- |
| [`User`](../../../backend/src/main/java/com/localmind/user/entity/User.java) | entity | `users` row |
| [`UserRepository`](../../../backend/src/main/java/com/localmind/user/repository/UserRepository.java) | repository | `JpaRepository<User, String>` + `findByEmail`, `existsByEmail` |

## HTTP API

None. The profile is exposed by `GET`/`PATCH /api/auth/me` in the [auth feature](auth.md#http-api).

## Domain model

### `users` (`User`)

Schema is generated by Hibernate (`ddl-auto`, default `update`).

| Column | Type | Constraints | Default |
| --- | --- | --- | --- |
| `id` | `VARCHAR(36)` | PK, not null | random UUID in `@PrePersist` |
| `email` | `VARCHAR(255)` | not null, unique | |
| `password_hash` | `VARCHAR(255)` | not null (BCrypt hash written by `AuthService`) | |
| `full_name` | `VARCHAR(100)` | nullable | |
| `custom_instructions` | `TEXT` | nullable | |
| `created_at` | timestamp (`Instant`) | not updatable | `Instant.now()` in `@PrePersist` |

Relations: none mapped. `refresh_tokens`, `conversations`, `user_memories` and `attachments` hold a plain
`user_id VARCHAR(36)` column with no foreign key.

`UserRepository` queries: `findById`, `findByEmail(String)`, `existsByEmail(String)` (callers pass the normalised,
lower-cased email; the repository itself does not normalise).

## Business rules

1. The entity enforces no rules beyond column constraints; email normalisation (trim + lower case) and password
   hashing are done by `AuthService` before saving.
2. Users are never deleted by application code: there is no delete endpoint or service method, so no cascade to
   conversations, memories, attachments, files or vectors exists.

## Side effects & async work

None.

## Configuration

None.

## Errors

None thrown by this feature. `User not found` errors (401 `UnauthorizedException`, an invalid session) come from callers (see [auth](auth.md#errors)).

## Interactions with other features

- `auth.service.AuthService`: creates users, looks them up by email/id, updates `fullName`/`customInstructions`.
- `auth.service.JwtService` and `auth.dto.UserSummary`: read `User` fields for token claims and responses.
- `chat.prompt.advisor.PromptStructureAdvisor`: `findById` to append the user's `customInstructions` to the system prompt.
- This feature depends on nothing else.
